# SEO 기반 정비 — sitemap · robots · JSON-LD · OG 이미지

## Background (Why)

사이트는 라이브(`https://dohapark81.github.io/threepowers/`)이고 정적 HTML(SSG)이라 크롤링 차단은 없다.
그러나 색인 발견을 돕는 `sitemap.xml`·`robots.txt`가 404이고, 리치 결과용 구조화 데이터(JSON-LD)와
SNS 공유 미리보기(`og:image`/트위터 카드)가 빠져 있어 "검색에 잘 잡히는" 부분이 절반만 구현돼 있다.

## Goal (What)

검색엔진이 전 페이지를 빠르게 발견·색인하고, SNS 공유 시 썸네일이 뜨며, 리치 결과 후보가 되도록
SEO 기반 자산 4종을 추가한다. 콘텐츠/데이터는 일절 건드리지 않는다(원칙: 결론 없음·중립 유지).

## Scope

### Files to modify / create

| File | Task | Description |
|------|------|-------------|
| `astro.config.mjs` | T1 | `@astrojs/sitemap` 통합 추가 |
| `package.json` / lockfile | T1 | 의존성 추가(자동) |
| `public/robots.txt` | T2 | 신규 — `public/` 디렉터리 자체가 없으므로 함께 생성 |
| `src/layouts/Base.astro` | T3·T4 | `<head>`에 JSON-LD + OG/트위터 메타 추가 |
| `public/og.png` | T4 | 신규 — 1200×630 대표 이미지 1장 |

**Out of scope (do not touch)**

- `data/*.json`, 본문 콘텐츠, 카피, 결론/판정 톤
- `src/pages/*`의 데이터 렌더링 로직
- 커스텀 도메인 전환(D7) — 별도 WI

## Impact Analysis

### ⚠ 핵심 함정 — GitHub Pages 프로젝트 페이지의 robots.txt

robots.txt 표준은 **호스트 루트**(`https://dohapark81.github.io/robots.txt`)에서만 읽힌다.
이 저장소가 배포되는 `…/threepowers/robots.txt`(서브경로)는 **구글이 사이트 robots 정책으로 인정하지 않는다.**
즉 T2의 `public/robots.txt`는 그 자체로는 크롤 지침/Sitemap 선언의 권위를 갖지 못한다.

→ 결론: **sitemap 발견의 신뢰 경로는 robots.txt가 아니라 Search Console 직접 제출(아래 Runbook)이다.**
   `public/robots.txt`는 (a) 무해하고 (b) 커스텀 도메인(D7) 전환 시 즉시 유효해지므로 그대로 넣되,
   호스트 루트 robots는 별도 저장소(`dohapark81.github.io` user-page)에서 관리해야 함을 인지할 것.

### Side-effect risk areas

- `base: '/threepowers'` 때문에 모든 절대 URL은 base를 포함해야 한다. sitemap/OG/canonical/JSON-LD URL이
  `…/threepowers/…` 로 나오는지 빌드 산출물에서 반드시 확인(AC에 포함).
- `Astro.site`(`https://dohapark81.github.io`) + base 조합으로 절대 URL을 만들 것. 하드코딩 금지.

### risk_level: low 근거

단일 레이아웃 파일 head 추가 + 빌드타임 통합 1개. 런타임/데이터/스키마 변경 없음. 롤백은 커밋 revert로 충분.

## Implementation Guide (How)

> 4개 태스크는 독립적으로 빌드·검증 가능. T1→T2→T3→T4 순서 권장(의존성은 없음).
> 각 태스크 완료 시 `npm run build`로 산출물 확인 후 다음으로.

### T1 — sitemap (`@astrojs/sitemap`)

```bash
npx astro add sitemap --yes
```

결과로 `astro.config.mjs`가 아래처럼 되어야 한다(자동 적용 안 되면 수동 반영):

```js
// @ts-check
import { defineConfig } from 'astro/config';
import sitemap from '@astrojs/sitemap';

export default defineConfig({
  site: 'https://dohapark81.github.io',
  base: '/threepowers',
  integrations: [sitemap()],
});
```

- 통합은 `site`+`base`를 자동 반영 → 산출물 URL이 `https://dohapark81.github.io/threepowers/…` 로 나온다.
- `rss.xml` 같은 비페이지 엔드포인트는 sitemap에 안 들어가는 게 정상.

### T2 — robots.txt

`public/robots.txt` 신규 생성(디렉터리 없으면 `public/`도 생성):

```
User-agent: *
Allow: /

Sitemap: https://dohapark81.github.io/threepowers/sitemap-index.xml
```

> 위 "핵심 함정" 참고: 서브경로 robots는 비권위. Sitemap 등록의 실제 효력은 Runbook의 Search Console 제출로 확보한다.

### T3 — JSON-LD 구조화 데이터 (`src/layouts/Base.astro`)

frontmatter(`---` 블록)에 절대 URL 계산 추가:

```astro
const base = import.meta.env.BASE_URL.replace(/\/$/, '');
const canonical = new URL(Astro.url.pathname, Astro.site);          // 절대 canonical
const siteUrl = new URL(`${base}/`, Astro.site).href;              // https://dohapark81.github.io/threepowers/
const ogImage = new URL(`${base}/og.png`, Astro.site).href;        // T4에서 사용

const jsonLd = {
  '@context': 'https://schema.org',
  '@type': 'WebSite',
  name: '삼권 threepowers',
  url: siteUrl,
  inLanguage: 'ko',
  description: '중앙선거관리위원회·헌법재판소·대법원의 구성과 6·3 사태 기록을 공식 원문 링크와 함께 날짜순으로 기록. 결론을 내리지 않습니다.',
  publisher: { '@type': 'Organization', name: '삼권 threepowers', url: siteUrl },
};
```

`<head>` 안(닫는 `</head>` 직전)에 추가:

```astro
<script type="application/ld+json" set:html={JSON.stringify(jsonLd)} />
```

- 중립 원칙 준수: Organization 설명에 판정/결론/당파 톤 금지. 위 문구 그대로 권장.
- (선택, 별도 가능) `election-commission/members` 페이지에 `Dataset` 타입 JSON-LD 추가 — 본 WI에선 site-level만 필수.

### T4 — OG 이미지 + 트위터 카드 (`src/layouts/Base.astro`)

`<head>`의 기존 og 태그 묶음에 아래를 보강(누락분: `og:url`·`og:site_name`·`og:image`·트위터):

```astro
<meta property="og:url" content={canonical} />
<meta property="og:site_name" content="삼권 threepowers" />
<meta property="og:image" content={ogImage} />
<meta property="og:image:width" content="1200" />
<meta property="og:image:height" content="630" />
<meta name="twitter:card" content="summary_large_image" />
<meta name="twitter:title" content={`${title} · 삼권 threepowers`} />
<meta name="twitter:description" content={description} />
<meta name="twitter:image" content={ogImage} />
```

이미지 자산 `public/og.png` (**1200×630 PNG**) 1장 필요:
- 디자인 가이드: 검정 배경 + "삼권 三權 / threepowers" + 한 줄 설명("6·3 사태 공식 기록 · 결론 없음"). 브랜드 톤은 `global.css` 참고.
- crew에 디자인/이미지 에이전트가 없음 → (a) 사용자가 1장 제공하거나 (b) 실행자가 정적 PNG를 생성. 텍스트만 있는 단순 이미지로 충분.
- 임시로 미준비 시: `og:image` 라인만 두고 이미지는 후속 추가 가능하나, **AC 통과 = 이미지 200 OK** 이므로 본 태스크 완료엔 실제 파일 필요.

## Manual Runbook — Google Search Console (코드 아님, 사람이 콘솔에서)

> 위 4개 코드 태스크가 배포된 뒤 진행. sitemap 효력의 실제 경로(robots 함정 우회).

1. Search Console → **URL 접두어** 속성 추가: `https://dohapark81.github.io/threepowers/`
2. **소유권 확인 = HTML 파일 업로드** 방식 사용:
   - 콘솔이 주는 `googleXXXX.html` 을 `public/`에 넣고 배포 → `…/threepowers/googleXXXX.html` 200 → 확인 클릭
   - (DNS/도메인 방식은 도메인 미보유로 불가)
3. **Sitemaps** 메뉴 → `sitemap-index.xml` 제출(속성 기준 상대경로)
4. **URL 검사** → 주요 4개 페이지 "색인 생성 요청"
5. 며칠 후 `site:dohapark81.github.io/threepowers` 로 색인 진입 확인
