# 사태기록 상단 핵심 흐름 칩 스트립 — 전환점 6건 압축 요약

## Background (Why)

사태기록(timeline) 페이지는 `6·3 메인(16건) + 채용비리 배경(8건)`이 세로로 길게 쌓여 있어,
처음 방문한 사람이 "무슨 일이 어떤 순서로 터졌는지"를 3초 안에 파악할 한눈 요약 층이 없다.
전체 날짜순 리스트 **위에**, 사태의 전환점만 6개로 압축한 "핵심 흐름" 칩 스트립을 깔아
요약 → 상세 드릴다운 동선을 만든다.

## Goal (What)

타임라인 페이지 상단(제목·리드 **아래**, 첫 전체 리스트 **위**)에 **핵심 흐름 칩 스트립**을 추가한다.
칩 하나 = `[● 날짜 · 짧은 라벨]` 형태이고, 누르면 아래 전체 기록의 해당 항목 앵커로 점프한다.
"어느 항목이 전환점인가"는 데이터에 **명시 플래그(`pivot`)**로 박아 큐레이션을 git에 투명 공개하고,
선정·라벨 규칙을 `data/README.md`에 명문화한다. 6·3 메인 기록만 대상이며, 채용비리 배경 섹션은 불변.

## Implementation Guide (How)

> 판단 불필요 수준으로 구체화함. 라벨 값·선정 항목은 planner가 확정했으니 **그대로** 박을 것.

### T1 — 타입 + 데이터 + 규칙 문서

**(a) `src/lib/types.ts`** — `EventRef` 인터페이스 부근에 추가하고, `TimelineEvent` 에 필드 한 줄 추가:

```typescript
/**
 * 핵심 흐름 칩(전환점 요약)에 노출할 항목 표시.
 * 선정·라벨 규칙은 data/README.md 참조.
 * 라벨은 제목에서 뽑은 사실 조각만 — 판정·인과·형용 금지.
 */
export interface PivotMark {
  /** 칩에 표시할 짧은 사실 라벨. 예: "투표 중단·재개" */
  label: string;
}
```

`TimelineEvent` 인터페이스에 (topics 위/아래 아무 곳):

```typescript
  /** 핵심 흐름 칩 노출 표시 (선택). data/README.md 의 선정 규칙을 따른다 */
  pivot?: PivotMark;
```

**(b) `data/events.json`** — 아래 **6개 항목에만** `pivot` 추가. id로 찾아서 각 객체에 키 추가
(기존 필드는 절대 수정하지 말 것). 날짜 오름차순 = 사태 전개 순:

| event id | 추가할 필드 |
|----------|-------------|
| `evt_20251210_01` | `"pivot": { "label": "인쇄하한 60→50%" }` |
| `evt_20260603_01` | `"pivot": { "label": "투표 중단·재개" }` |
| `evt_20260605_04` | `"pivot": { "label": "위원장 사퇴 표명" }` |
| `evt_20260608_01` | `"pivot": { "label": "국정조사 요구" }` |
| `evt_20260609_03` | `"pivot": { "label": "합수본 출범" }` |
| `evt_20260611_01` | `"pivot": { "label": "7곳 압수수색" }` |

> 라벨은 전부 각 항목 `title` 원문에서 뽑은 사실 조각이다(판정·형용 없음). 임의 변경 금지.
> 이 6개는 6·3 사태의 전환점(원인지침 → 발발 → 책임자 사퇴 → 입법대응 → 수사착수 → 강제수사)이다.

**(c) `data/README.md`** — 새 섹션 추가 (기존 가드레일 톤에 맞춰):

```markdown
## 핵심 흐름 칩(pivot) 선정·라벨 규칙

사태기록 상단의 "핵심 흐름" 칩은 전체 기록 중 **전환점만** 압축한 요약 층이다.
선정은 편집 행위이므로 데이터에 명시 플래그(`pivot`)로 박아 git에 투명 공개한다.

- **범위**: `events.json`(6·3 메인)만. `recruitment_events.json`(채용비리 배경)은 칩에 넣지 않는다.
- **개수**: 최대 6~7개. 압축이 목적이므로 늘리지 않는다.
- **선정 기준**: 사태의 국면을 바꾼 전환점(원인 지침 / 사태 발발 / 최고책임자 거취 /
  입법부 대응 / 수사 착수 / 강제수사 등). 같은 국면의 중복·후속 발표는 대표 1건만.
- **라벨 가드레일**: 해당 항목 `title` 에서 뽑은 **사실 조각만** 쓴다.
  - 허용: "투표 중단·재개", "위원장 사퇴 표명", "7곳 압수수색"
  - 금지: 판정·인과·형용 단독 사용("선관위 은폐", "특혜 채용" 등). 공식 처분 문구 인용은 예외.
- 추가·삭제는 `events.json` 의 해당 항목에서 `pivot` 한 줄을 켜고 끄면 된다(코드 변경 불요).
```

### T2 — `src/components/KeyEvents.astro` (신규)

전체 파일을 아래로 생성. `TimelineList.astro` 의 `STATUS_CLASS`·앵커 규칙을 그대로 따른다:

```astro
---
import type { TimelineEvent } from '../lib/types';

interface Props {
  events: TimelineEvent[];
  /** 항목 앵커 링크의 베이스 경로. 같은 페이지면 빈 문자열 */
  anchorBase?: string;
}
const { events, anchorBase = '' } = Astro.props;

// pivot 표시된 항목만, 날짜 오름차순(전환점을 전개 순서대로 좌→우)
const pivots = events
  .filter((e) => e.pivot)
  .sort((a, b) => a.date.localeCompare(b.date) || a.id.localeCompare(b.id));

// TimelineList 와 동일한 상태→색 매핑
const STATUS_CLASS = {
  official: 'b-official',
  investigating: 'b-progress',
  result_announced: 'b-result',
  corrected: 'b-correct',
} as const;

// 6·3 사태 표기 관례: 'YYYY-MM-DD' → 'M·D'
const shortDate = (d: string) => {
  const [, m, day] = d.split('-');
  return `${Number(m)}·${Number(day)}`;
};
---

{pivots.length > 0 && (
  <div class="keyflow">
    <span class="keyflow-label">핵심 흐름</span>
    <div class="stages-scroll">
      <div class="keyflow-chips">
        {pivots.map((evt) => (
          <a class="kchip" href={`${anchorBase}#${evt.id}`}>
            <span class:list={['kdot', STATUS_CLASS[evt.status]]} />
            <span class="kdate">{shortDate(evt.date)}</span>
            <span class="klabel">{evt.pivot!.label}</span>
          </a>
        ))}
      </div>
    </div>
  </div>
)}
```
