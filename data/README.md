## 수록 원칙

- **원문 링크 100%.** `url: null`은 "원문 공개 대기" 상태로만 일시 허용되며, 사이트에 "원문 확인 중"으로 노출된다. 공개 전까지 모든 null을 해소하는 것이 목표.
- 출처 등급은 `official`(선관위·국회·관보) 또는 `press_multi`(복수 매체 교차 확인)만. 단독 보도는 수록하지 않는다.
- 상태 라벨은 4종만: `official | investigating | result_announced | corrected`. 4종 어디에도 맞지 않는 항목(예: 전문가 분석·논평)은 수록하지 않거나 별도 구조를 신설한 뒤 담는다.
- 정정은 삭제가 아니라 새 항목 + `supersedes`로 표현한다. 정정이 아닌 일반 연결(원인→결과, 주장→공식대응)은 `related`로 잇는다.
- **2차 분석·논평·오피니언은 출처로 채택하지 않는다.** 그런 글의 내부 사실 주장은 1차 출처(official 또는 press_multi)로 역추적해 중립 서술로만 수록하고, 역추적이 안 되면 등록하지 않는다. 글의 결론·판정·당파적 표현은 어떤 경우에도 수입하지 않는다.
- **주장은 판정하지 않고 공식 대응만 기록한다.** 음모론·의혹성 주장 자체를 항목으로 싣지 않으며, 그에 대한 공식 대응(법원·기관 발표 등)이 생긴 시점에 그 공식 행위를 앵커로 등록한다. 사건의 시점을 임의로 옮겨 적지 않는다(예: 과거 사건을 6·3 타임라인에 끼워 넣지 않음).
- 6·3 이전의 배경 사건이 필요하면 `events.json`에 섞지 말고 별도 데이터셋으로 분리한다. 현재 채용 비리 배경 기록은 `recruitment_events.json`으로 따로 관리한다.
- `topics`는 `src/lib/types.ts`의 `TOPICS` 통제 어휘만 사용한다. 새 토픽은 배열에 먼저 추가한다.
- 이 디렉토리의 변경은 에이전트가 PR까지만 만들고, 머지는 반드시 사람이 한다.

## 핵심 흐름 칩(pivot) 선정·라벨 규칙

사태기록 상단의 "핵심 흐름" 칩은 전체 기록 중 **전환점만** 압축한 요약 층이다.
선정은 편집 행위이므로 데이터에 명시 플래그(`pivot`)로 박아 git에 투명 공개한다.

- **범위**: `events.json`(6·3 메인)만. `recruitment_events.json`(채용비리 배경)은 칩에 넣지 않는다.
- **개수**: 최대 6~7개. 압축이 목적이므로 늘리지 않는다.
- **선정 기준**: 사태의 국면을 바꾼 전환점(원인 지침 / 사태 발발 / 최고책임자 거취 /
  입법부 대응 / 수사 착수 / 강제수사 등). 같은 국면의 중복·후속 발표는 대표 1건만.
- **라벨 가드레일**: 해당 항목 `title` 에서 뽑은 **사실 조각만** 쓴다.
  - 허용: "투표 중단·재개", "위원장 사퇴 표명", "7곳 압수수색"
  - 금지: 판정·인과·형용 단독 사용("선관위 은폐", "특혜 채용" 등). 공식 처분 문구 인용은 예외.
- 추가·삭제는 `events.json` 의 해당 항목에서 `pivot` 한 줄을 켜고 끄면 된다(코드 변경 불요).
